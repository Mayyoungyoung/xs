# Novel-Agent System 实施路线图

## Phase 0：项目初始化

- 确定首版形态：Web App、桌面 App、CLI 或纯 API。
- 选定技术栈。
- 建立代码规范、环境变量规范、测试框架与基础 CI。
- 明确模型供应商配置格式与密钥存储方式。

验收标准：

- 本地可以启动空白应用或 API 服务。
- 可以读取配置但不会泄露 API Key。

## Phase 1：多书籍沙盒与资产管理

- 创建、切换、删除书籍。
- 每本书拥有独立资产空间。
- 支持世界观、人物卡、章节大纲、章节正文、章节快照的 CRUD。
- 所有资产支持版本历史。

验收标准：

- A 书的资产不会出现在 B 书中。
- 删除书籍时可以清理对应资产与索引。
- 已确认资产被修改时生成新版本。

## Phase 2：模型路由与 Agent Runtime

- 配置模型供应商。
- 为 Architect、Writer、Continuity Editor、Stylist 分配模型。
- 实现统一模型调用接口。
- 记录 token、耗时、错误与成本估算。
- 支持 fallback 模型。

验收标准：

- 四个 Agent 可以使用不同模型执行同一工作流。
- 模型调用失败时按策略重试或切换 fallback。
- 每次调用都有可审计日志。

## Phase 3：闸口工作流

- 实现工作流状态机。
- 每个核心节点进入待确认状态。
- 用户可以批准、驳回、插话中断、提交修改意见。
- 修改意见触发新一轮生成并保留版本记录。

验收标准：

- 未经用户确认，系统不会自动推进到下一核心节点。
- 运行中任务被中断后，当前上下文和部分输出可追溯。

## Phase 4：宏观设定与中观大纲

- Architect 生成世界观白皮书。
- Architect 生成深度人物卡。
- Architect 生成分卷大纲与章节大纲。
- 强制校验章节大纲字段完整性。

验收标准：

- 章节大纲必须包含核心冲突、出场人物、主/支线推进目的、章尾钩子。
- 设定、人物卡、大纲都经过闸口确认。

## Phase 5：章节生成闭环

- Writer 根据章节大纲生成正文。
- Continuity Editor 审查正文。
- blocker 问题触发重写。
- Stylist 润色终稿。
- 用户确认后生成章节快照。

验收标准：

- 每章最终产物包含初稿、审查报告、润色稿、章节快照。
- 审查报告能引用冲突来源。
- 章节快照写入记忆库。

## Phase 6：RAG 记忆外挂

- 建立每本书独立向量命名空间。
- 写入世界观、人物卡、章节快照、检索素材。
- 章节生成前自动检索上下文包。
- Continuity Editor 使用同一上下文包审查。

验收标准：

- 生成章节时不会检索到其他书籍资料。
- 上下文包至少包含世界观、相关人物卡、当前章节大纲、最近章节快照。

## Phase 7：素材检索与文风分析

- 支持按题材/核心梗检索公开结构化信息。
- 生成风向报告。
- 支持用户上传或粘贴文风样本。
- 生成 Style Prompt。

验收标准：

- 风向报告包含标签、高频词、爽点、避雷点、差异化建议。
- Style Prompt 描述句式、节奏、修辞、视角、禁忌，不输出长段仿写正文。

## Phase 8：产品化增强

- 前端工作台完善。
- Agent 群聊可视化。
- 版本对比。
- 导入导出。
- 成本与用量面板。
- 备份、恢复、审计日志。

验收标准：

- 作者可以在一个工作台里完成从设定到章节终稿的闭环。
- 所有关键输出可追溯、可比较、可回滚。
