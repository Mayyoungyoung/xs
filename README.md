# 墨脉 · AI 小说工作台

面向长篇中文小说的本地创作应用，包含 Windows 桌面软件、Web 工作台与 Python CLI。世界观、人物、世界线、大纲、文风、章节、借鉴与对话按书籍隔离保存。

## Windows 桌面软件

发给别人安装时，只需发送 Releases 附件中的 `Momai-Setup-1.3.0-x64.exe`（或在本地 `desktop-release/` 下生成后发送）。这是包含完整运行组件的 Windows 10/11 x64 安装包，接收者双击后可在「选择安装位置」页选择 D 盘等文件夹，安装后通过桌面或开始菜单中的「墨脉小说创作」启动，无需安装 Node.js 或启动网页服务。程序支持在 Windows 设置中卸载。

安装包只包含程序，不包含本机小说或 API 密钥。每位使用者在软件设置中填写自己的模型密钥（支持 DeepSeek、Moonshot Kimi、智谱 GLM、阿里通义、OpenAI、Anthropic、Google Gemini、OpenRouter 与自定义 OpenAI 兼容接口）。当前安装包没有代码签名，Windows 下载保护可能显示未知发布者；应从可信来源取得安装文件并核对发布者提供的 SHA-256。

也可直接运行 `desktop-release/Momai-win32-x64/Momai.exe`，但此方式必须保留同目录全部文件，不能只把这个 exe 发给别人。

- 小说首次默认保存至 `%APPDATA%\MomaiNovel\data\library.json`。在「模型设置 → 小说存储位置 → 更改位置并迁移」选择新的空文件夹（例如 `D:\小说资料`），校验成功后立即切换到新位置，无需重启。
- 全部小说、章节、世界线、讨论、版本、自动备份、模型选择和本机加密密钥一起迁移。迁移期间的保存请求会排队并写入新位置；新位置已有内容时拒绝覆盖，失败时仍使用原目录。旧目录暂时保留，核对后可自行清理。
- 启动定位配置 `%APPDATA%\MomaiNovel\storage-location.json` 和界面缓存仍在系统用户目录，小说资料不必放在 C 盘。如果自定义磁盘离线或书架文件丢失，软件会明确提示，不会创建空书架覆盖。
- 自动备份在同目录的 `backups`，保留最近 20 份；每次启动后的首次更新会备份，持续编辑时两次备份至少间隔 5 分钟。可从软件中的「导入项目」恢复备份。
- 模型密钥在设置中填写，使用 Windows 本机加密后独立保存，重启仍可使用，不进入小说导出文件。
- 网页版与桌面版的数据独立。迁移已有小说：网页版书架「导出备份」→ 桌面版书架「导入项目」。完整备份含正文、世界线、讨论和版本；原网页版数据保留。
- 本地编辑无需联网，AI 创作与资料检索需要网络和相应模型密钥。

重新制作安装包（开发者需要 Node.js 与 [Inno Setup 6/7 编译器](https://jrsoftware.org/isdl.php)）：

```powershell
cd webapp
npm ci
npm run desktop:installer
```

默认识别 Inno Setup 常见安装位置；也可设置 `ISCC_PATH` 为 `ISCC.exe` 完整路径。首次打包需要下载 Electron 运行组件。也可将对应版本的 Windows x64 官方 zip 放在 `webapp/desktop-runtime/`，打包时会验证官方 SHA-256 后使用。安装包以当前 Windows 用户安装，所选文件夹需要可写；更新和卸载不会删除独立的数据目录。当前没有自动更新。

## 网页版开始使用

需要 Node.js 22.15+。Windows 可在项目目录运行：

```powershell
.\start.ps1
```

也可以手动启动：

```powershell
cd webapp
npm ci
Copy-Item .env.example .env.local  # 仅首次运行；不要覆盖已有密钥配置
npm run dev
```

打开 **http://localhost:5173**。保持使用同一浏览器和同一地址：`localhost` 与 `127.0.0.1`、不同端口的本地数据互不共享。

无需密钥即可创建小说、编辑设定与章节、保存、恢复和备份。启用 AI：

1. 在书架或小说工作区点击「模型设置」。
2. 选择模型供应商（DeepSeek、Moonshot Kimi、智谱 GLM、阿里通义千问、OpenAI、Anthropic Claude、Google Gemini、OpenRouter 聚合，或自定义 OpenAI 兼容接口），粘贴对应 API Key。
3. 选择该供应商下的创作模型；每家都列出常用型号，也可选「自定义模型名…」填写供应商文档中的模型 ID。
4. 点击「验证并保存」：软件先发送一句简短测试消息验证密钥可用（消耗少量额度，不发送小说内容），验证通过才保存并启用；验证失败会给出原因且不保存。也可用「测试连接」单独检查已保存的密钥。

界面填写的密钥保存在当前标签页的 sessionStorage 中，刷新后可继续使用；不会写入书籍数据库或导出备份，可随时点击「清除密钥」。如需服务端统一配置，可在 `webapp/.env.local` 设置 `MOMAI_PROVIDER` + `MOMAI_API_KEY`（或各家独立变量如 `OPENAI_API_KEY`、`ANTHROPIC_API_KEY`；`DEEPSEEK_API_KEY` 仍兼容）后重启。当前标签页密钥优先于服务端配置。

自定义 OpenAI 兼容接口面向本地或自建服务（如 Ollama、LM Studio、vLLM）：填写到 `/v1` 为止的接口地址和模型名。接口地址仅接受 https，或本机回环地址的 http（如 `http://127.0.0.1:11434/v1`）；已知供应商的官方端点不能被改写，避免把密钥发到其他地址。Anthropic 与 Gemini 使用各自官方协议，OpenAI 推理系模型（gpt-5、o 系列等）自动改用对应参数。

## 统一共创：自己写 / AI 生成 / 一起讨论

第二轮修复（共创闭环与真实章节分区）：

- **采纳收敛为单一事务**：目标存在性、书籍归属、候选是否仍待采纳、内容是否在生成后变化、字段范围、锁定、引用与最终 schema 一次校验；成功后正式内容、候选状态、修改前快照与讨论记录在同一次更新中落盘。失败、目标不存在或校验不通过时不会标记已采纳，也不会显示已保存。重复采纳以候选编号幂等，不依赖文本比较。
- **局部修改与锁定是代码约束**：针对某个事件的候选不能夹带修改其他事件或范围外字段；无论从事件、故事线还是整图入口采纳，都检查**实际被改对象**的锁定。锁定由代码执行，不依赖提示词要求模型自觉遵守；作者本人手写不受 AI 锁影响。
- **进度变化单独确认**：把事件标记为「已写完」需要作者显式确认——AI 改剧情不等于事件已写完。
- **新增事件与关联成组**：在暂存图上按依赖顺序校验，「新增事件后关联它」可整组采纳；引用不存在的 ID 时整组拒绝，不留悬空引用或半途应用。
- **选区不再静默重定位**：锚点或版本失效即阻止自动替换并要求重新选择；仅当上下文能唯一确定新位置时才提供「按新位置替换」，且需作者点击确认。两句相同台词、生成期间在前文插入文字等情况都不会改错位置。
- **润色、续写与局部改写走同一生成控制器**：结果一律成为绑定原章节的候选，正文不自动改变，可对比、编辑、采纳与恢复；失败或取消不产生半成品，也没有未处理的 Promise rejection。生成、讨论与审查都不会顺便写入章节的推荐事件绑定——推荐计划只作为本次请求的参考，`plotEventIds` 仍由作者在章节中确认。
- **上下文单一来源**：界面「本次会带上什么」与请求 payload 由同一份上下文包生成，裁剪会明确提示；各模块只发送本模块范围的借鉴，显示与实际发送一致；模型连接状态与数据保存状态分开显示。
- **讨论转候选按目标类型**：文本目标产出可采纳文本，事件/故事线目标产出受限的结构化修改；「引用最后一条建议」是明确标注的引用，不冒充「整理」。未发送的讨论草稿按目标保存，切换节点再回来不会清空。
- **剧情候选显示字段级差异**：候选列出每个字段的 before/after 与受影响事件，可只勾选其中几项采纳；结构化多方向改为「讨论三个方向」，不再用文本分隔符冒充结构化方案。
- **真正的章节分区画布**：章节绑定决定章节区，区内按叙事顺序在不同泳道间共用槽位，冲突卡片才增加槽位；未绑定事件进入独立的「待安排章节」计划区。区有明确起止与宽度，节点必定落在所属区内，卡片不重叠。章节文字与绑定矛盾时提示，绝不改写作者数据。
- **画布交互**：聚焦按事件所属的全部故事线判断（共享事件在任一线聚焦时保持可见）；折叠真正移除节点与连线并保留摘要，搜索命中折叠线时提示可展开；语义缩放一次按缩放比例到达正确层级；视口按书保存且滚动时防抖写入（一次手势只写一次，离开页面时补写最终位置）。AI 待采纳修改在原画布上用虚线标记。手工编辑表单在正式内容被更新（例如刚采纳 AI 修改）后会拒绝用旧草稿覆盖，并提示重新载入。
- **两种剧情视图不混轴**：默认「章节分区视图」（绑定决定分区，区内按叙事顺序、跨泳道共用槽位）；可切换「叙事顺序视图」，严格按叙事顺序排布，章节只作为事件卡上的属性。视图选择按书保存。
- **单一 Inspector**：事件与故事线的可编辑字段和共创面板同处世界线右侧栏，点节点不再退出专注、不再跳到页面底部，画布旁也不会出现第二份表单；窄屏下该侧栏变为覆盖抽屉。

每个创作模块（故事蓝图、世界观、人物、文风、大纲、章节、世界线的事件与故事线）都使用同一个共创侧栏，三种方式操作同一份内容：

- **自己写**：主编辑区始终可直接编辑，选择文本后 AI 只针对选区工作。
- **讨论**：按「书籍 + 模块 + 具体目标」分线程保存，默认只给建议，不会改动正式内容；满意后再「整理为候选稿」。讨论按模块隔离，不会混入其他模块。
- **生成**：直接产生候选稿，同样不会自动写入；一次只生成一个候选，只有点「给我三个方向」才生成多个。

候选稿统一记录目标、原始内容哈希、选区锚点与状态；采纳时提供「替换选中内容 / 插入到选中之前 / 插入到选中之后 / 整体替换 / 追加到末尾」，并保证：

- 生成期间作者若修改了原文，整体替换会被拒绝并说明原因；选区锚点失效时提示重新选择，不会猜插入位置。
- 采纳前先校验目标是否已变化；重复点击或重复响应不会重复写入。
- 切换书籍或章节后，迟到的响应仍绑定生成时的目标，不会写进当前页面。
- 「锁定」可阻止 AI 改写该目标，AI 仍可继续讨论与给建议。
- 一次采纳只保留一个可恢复快照，不会造成快照膨胀。
- 采纳后的内容进入正常保存流程；无密钥时手写、图编辑与保存完全可用，不会用模拟内容冒充生成成功。

## 世界线：剧情泳道图

- 布局由纯函数生成（`lib/story-graph.ts`）：主线在上、支线在下，横向按叙事推进顺序，并按真实章节绑定划分阶段，未绑定章节的事件进入明确的「待安排章节」计划区。
- 分级显示随缩放切换：远景只看故事线与进度，中景显示事件标题/章节/状态，近景补充摘要与操作提示；缩放不会改变数据内容。
- 工具栏提供搜索（默认淡化无关项而不是重排画布）、定位当前章节、聚焦某条故事线、折叠/展开故事线、适应宽度与展开大图；视图位置与显示层级按书保存，且不计入内容修订。
- 共享事件只保留一个事件 ID：主线显示主卡片，其他引用它的线显示锚点，修改与完成状态同步；交汇关系用竖线连接，图例区分本线推进、支线衍生与共享事件。
- 事件仍可关联到章节并被章节正文反向引用；章节重命名或排序不会破坏绑定。章节文字无法对应真实绑定时会提示，不会按文字强行排期。
- AI 的剧情修改以受限操作（修改事件字段 / 新增事件 / 关联已有事件 / 修改故事线）返回，先做结构、目标、引用与字段校验，再以虚线框在原画布上预览；未采纳前不计入进度，也不会成为正文事实。

## 完整创作流程

1. **书架**：创建、搜索、按最近编辑/书名/准备度排序、删除和导入导出。章节数与字数来自实际稿件；示例书仅提供故事种子，准备度为 0%。准备度按世界观、人物、世界线、文风、大纲与正文 6 项实际内容统计，不表示全书完成度。
2. **故事蓝图**：编辑故事种子和偏好，完善构思；完善结果先预览后采纳；支持保存与恢复整个故事的快照。顶部有明确的「返回书架」按钮；设置中可修改书名。
3. **独立模块**：故事蓝图只编辑构想与偏好；世界观、人物、文风、大纲、正文与借鉴库分别独立，通用助手按需展开。AI 读取当前书籍设定、编辑内容、主支线、前文和最近对话。
4. **世界线**：一条或多条主线与衍生支线按行展示，从左向右推进，共享事件连接多线交汇。每条线可编辑目标，每个事件可安排章节、选择与后果、写作进度。AI 支持讨论、生成多线方案、预览修改后采纳；旧版剧情自动映射为路线图，原时间说明收在可折叠的剧情笔记中，所有原数据保留。
5. **章节正文**：新建、切换、重命名、删除章节。支持续写、润色和连续性检查。生成先预览，可编辑预览，再替换或追加；离开页面后预览和审查仍保留。本章可绑定一个或多个世界线事件，生成以这些事件为目标，未来事件仅作为计划；作者确认本章完成后同步路线图进度。
6. **版本恢复**：采纳或恢复前保留原稿；可手动保存快照。每个编辑器保留最近 30 次快照，完整故事也保留最近 30 次。旧备份中的种子快照仍可恢复。
7. **共创助手**：连续对话、中文输入法发送保护、停止生成、错误提示、采纳到当前编辑器。清空对话不会删除设定和章节。
8. **借鉴资料**：组合检索网页、百科与图书元数据；部分来源不可用时保留其他结果。支持 TXT/Markdown/JSON，本地材料每份最多 2 MB、6 万字符，超限会提示拆分。
9. **导出**：单个设定或章节导出 Markdown；全部章节合并导出；书架 JSON 完整备份含正文、版本、借鉴、对话、生成预览与审查。

空白编辑器和默认 AI 要求按模块分别生成，并结合当前书名、题材、构想、已有故事线与本章事件调整；提示不会自动写入正文。路线图支持缩放、恢复 100%、适应宽度、展开大图与横纵滚动，缩放比例按书保存；展开后按 Esc 返回。

## 保存与恢复

- 浏览器 IndexedDB 保存完整书架，避免原先 localStorage 的小容量限制。旧版 localStorage 自动迁移，迁移源不会被删除。
- 书籍索引与工作区原子保存；状态只有在写入完成后才显示成功。
- 同时打开多页编辑时检测版本冲突，阻止旧页面覆盖新数据。冲突时先导出本页备份，再刷新。
- 读取损坏数据时不覆盖原始存储；写入失败时保留页面内容并明确提示备份。
- 讨论线程、候选稿、锁定与视图偏好随书籍一起保存和导出；解析时按条目宽容处理，个别损坏的线程或候选不会让整本书无法打开，旧版本备份（v2/v3）仍可正常读取。
- 讨论线程、候选稿与视图偏好不进入内容快照，也不会增加内容修订号，因此缩放、折叠、开关侧栏都不会产生无意义冲突。
- 导入前验证结构、书籍编号、章节编号与来源链接。同编号覆盖需要确认。删除书籍不可撤销，建议先导出备份；删除章节前自动保存完整快照。
- 本地数据库不是云同步。换设备、浏览器或地址时，请通过 JSON 备份迁移。清除网站数据会删除此地址的本地稿件。

## AI 的实际范围

- 当前 Web 端接入多家模型供应商（见上文列表），未配置密钥时不会用占位文本冒充生成。密钥、余额、限流、超时和返回格式错误有独立提示。DeepSeek 请求明确关闭默认思考模式，使正文输出预算用于创作内容。
- 为控制请求大小，模型上下文最多 12 万字符；当前正文取末尾 2.4 万字符，各设定最多 1.4 万字符，最近 3 章各取末尾 5000 字符；对话取最近 12 条，借鉴取最近 12 项、每项最多 1.2 万字符。长篇前文并非全部送入模型，请把关键事实维护在设定中。
- 单次输出最多 12000 tokens；若达到上限，会提示结果可能不完整。原稿保留，作者决定是否采纳。
- 联网借鉴来自公开摘要，不保证所有地区都能连接。CLI 的题材调研是模型建议，不能当作实时检索结果。
- 连续性检查是创作建议，仍需作者审阅。目前没有云端协作、向量记忆或自动发布。

## Python CLI

Python 3.10+，不需要外部依赖。

```powershell
python -m novel_agent init
python -m novel_agent create-book "雾城" --genre "悬疑" --premise "所有人忘记同一天"
python -m novel_agent list-books
python -m novel_agent --mock demo <book_id>
```

真实调用需在运行 CLI 的终端设置 `DEEPSEEK_API_KEY`；CLI 不自动读取 Web 的 `.env.local`。无密钥会明确提示演示模式，也可使用 `--mock`。CLI 与 Web 的稿件存储彼此独立。

```powershell
python -m novel_agent world <book_id>
python -m novel_agent characters <book_id>
python -m novel_agent outline <book_id>
python -m novel_agent draft <book_id> 1
python -m novel_agent revise <book_id> <artifact_id> --note "强化人物动机"
python -m novel_agent export <book_id> --output "exports/雾城.md"
```

每个产物可 `approve` 确认、`reject` 记录修改要求、`skip` 保留待确认。只有已确认的设定和章节快照进入后续上下文。章节生成前须确认世界观、人物与大纲。`demo` 按确认结果逐步推进；驳回或跳过即暂停。`revise` 生成独立修订稿并保留原稿；`export` 合并每章最新已确认稿件，避免覆盖现有文件。产物写入 `workspace/books/<book_id>`，JSON 使用原子替换。

## 已知限制与未验证项

- **没有真实截图**：开发环境里内置浏览器面板对系统不可见（`NATIVE_BROWSER_VIEWPORT_UNAVAILABLE`），无法产出 1366×768 / 1440×900 / 1920×1080 的界面截图；已用真实浏览器的结构断言替代（分区带、字段级差异、分项勾选、侧栏合并、视图切换、刷新后保留）。观感仍需本机目视确认。
- **Windows 125%/150% 系统缩放未测**：本环境无法设置系统 DPI；只验证了窄窗口（900 CSS px）下的紧凑分支与抽屉可用，这不等于系统缩放验证。
- **真实模型质量与各供应商连通性未测**：自动化测试使用确定性 mock，不消耗额度；需要配置真实密钥后各自验证一次。
- **500 节点样例未做**：当前 schema 上限是 16 条故事线 / 80 个事件，500 节点属于提高上限的范畴，本轮按要求未改上限。上限样例（16/80/20）已验证布局确定性与隔离渲染耗时。
- **未实现**：结构化人物卡、真实时间轴视图（故事时间与叙事顺序的显式分离）、拖动排序、小地图、跨设备的备选剧情版本管理；世界线仍是「章节分区 + 叙事顺序」两种视图，没有第三种时间语义。
- **分发限制**：安装包未做代码签名，Windows 会提示未知发布者；安装包通过 Releases 附件分发，不进仓库（超过 GitHub 单文件 100 MB 限制）。
